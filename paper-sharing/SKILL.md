# 论文分享

输入一篇论文，围绕论文基本信息和 A–G 框架生成中文分享内容，让没读过论文的听众理解问题、方法和主要收获。

## 表达与内容取舍

用自然、具体、好懂的话讲清楚重点，必要术语首次出现时顺带解释。按分享价值选择内容：核心问题、关键方法和有代表性的结果讲透，次要背景和过程细节简要带过。篇幅根据内容需要安排；需要缩短时先取舍内容，而不是逐句抠字、压缩成难懂的表达。

以正面叙述为主，直接说明方法做了什么、结果说明了什么。局限和不确定性在影响理解时简短交代，避免反复使用“不能说明”“并不意味着”“不是……而是……”等防御或反驳式句子。保持事实准确即可，不把分享稿写成审稿意见。

直接叙述具体内容，少加主观评价和强调。避免随手添加“很实用”“最值得注意”“非常巧妙”等判断性文字；确实影响理解核心贡献的内容才适度强调，并说明具体原因。

## 模式选择

- 纯文本文案模式（默认）：用户说“生成文案”“写分享稿”或未指定模式时使用。整个文案使用纯文本，仅必要的数学公式可使用公式排版。标题、正文、基本信息、引用和末尾参考资料均不使用 Markdown 格式，包括加粗、斜体、标题标记、表格、代码块、Markdown 链接及 Markdown 脚注语法，也不使用写作块或引用卡片包装。方法流程和比较用普通文字表达；G 节可按下方规则使用数字分点，引用按下方编号规则处理。
- 详细解释模式：用户要求解释、讲解论文，或明确指定此模式时使用。采用下方中英对照标题，可用 Markdown 和必要的行内公式辅助理解，正文仍按下方单段规则组织。

当前明确指定的模式优先。“详细生成文案”仍用纯文本。两种模式的章节内容要求相同，仅呈现形式不同。

## 阅读与资料使用

接受 PDF、链接、标题、DOI 或全文。围绕用户提供的论文阅读正文、方法、图表和实验，按需要查阅附录；标题或 DOI 输入时先找到对应原文。只能取得摘要或部分内容时，简短说明材料范围，依据现有材料分析。

所有小节均以论文本身和公开文献为基础。F 节优先采用论文的 Related Works 和参考文献，需要补充时再查找网上的原始论文。只有用户明确要求联系或比较本地工作时，才读取、分析相应本地材料；用户提供的目标论文本身可以是本地文件。

核对论文的发表或接收情况，优先查看会议、期刊官方页面及论文公开记录。已经发表或接收的论文，来源写具体会议或期刊及年份；即使阅读的是 arXiv 版本，也应注明正式去向。尚为预印本时写平台名称，可附已核实的学科分类。来源行只呈现来源信息，不附加“（已接受）”“（已发表）”“（xx月xx日检查未被收录）”等状态或检索过程说明。

关键结论与数字以原文为准，保留理解结果所需的指标和比较条件；关键结果可顺带标注图表或章节位置。引用其他论文时提供标题、年份和来源链接。自己的研究设想用“可以尝试”等自然措辞表达。

## 输出结构

先给基本信息，再按 A–G 顺序组织正文。根据用户指定的听众、时长和语言调整详略。默认直接在对话中交付分享内容。

两种模式中，每节标题单独一行，正文只写一段，节内不再分段或拆成表格、列表。G 节收获较多时可用“1. 2. 3.”分点，每点写成一段；其余小节保持单段。基本信息保留下面的四行格式。

G 节采用分点时，每点单独一行，相邻两点之间只换行，不留空行。

### 论文基本信息

两种模式均直接以以下四行开头，不另加节名：

论文完整标题
来源：具体会议/期刊及年份，或预印本平台
链接：论文来源的完整 URL
发布时间：YYYY年M月D日

发布时间使用来源标注的首次公开或发表日期，采用修订版本时按需要补充更新日期；仅能确认年份时写年份。查不到已接收只写平台即可，缺少的信息不标注。

### 文案模式的引用

正文中的必要引用使用普通文本编号 [1]、[2]，按首次出现顺序编号，同一来源重复使用同一编号。G 节之后另起“参考资料”一行，按编号逐行列出标题、年份与完整 URL，例如：[1] 论文标题，2026，https://example.org/paper。编号仅作为普通文字，不写成 Markdown 链接、引用式链接或脚注定义（如 [^1]）。正文引用处只放编号，不插入 Markdown 链接或来源卡片。

基本信息中的“链接：”一行保留目标论文的完整 URL，直接书写网址，不加链接文字、圆括号或尖括号；文内再引用该论文时，使用编号并在末尾参考资料中收录。其他参考来源的网址集中放在末尾。

### 节标题

纯文本文案模式使用以下普通文本标题：

A. 摘要
B. 研究问题
C. 输入输出
D. 技术路线
E. 实验验证
F. 相关工作
G. 核心收获

详细解释模式使用下方中英对照标题。两种模式均按以下要求选择重点组织内容，不必把每个问题逐条复述为问答。

### A. One-Sentence Summary｜一句话总结

这篇文章解决了什么问题，提出了什么方法？

### B. Research Problem & Challenge｜研究问题

研究目标是什么？
已有方法存在什么不足？
作者真正试图解决的核心 Challenge 是什么？

### C. Input & Output｜输入与输出

输入什么数据？
预测或生成什么？
模型训练需要哪些数据、标签或先验知识？

### D. Core Method｜核心技术路线

方法总体架构
Step 1 → Step 2 → Step 3
每一步在做什么，为什么需要这一步？
最核心的方法创新是什么？

### E. Experimental Evidence｜实验验证

使用什么数据集？
与哪些 Baselines 比较？
哪些结果真正支持作者的核心贡献？
泛化性和局限性如何？

### F. Connection to Previous Papers｜与已有文献的联系

和之前哪篇文章解决类似问题？
两者在方法上有什么区别？
是否解决了之前文章留下的问题？
能否与已有方法组合？

### G. Key Takeaways｜核心收获

1–3 个最值得记住的技术思想
对后续研究可能有价值的思路

## 交付前检查

通读正文，核对来源、关键事实和模式格式，确认每节为单段，G 节分点之间没有空行，来源行没有状态或检索附注。文案模式检查整个输出为纯文本（必要数学公式除外），引用为 [1]、[2] 并在末尾列出参考资料，网址没有被写成 Markdown 链接。删去重复背景、次要细节、多余限定句和随意添加的评价或强调，让主线连贯、重点清楚。
